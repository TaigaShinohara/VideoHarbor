# VideoHarbor

動画の直接保存と、タブ・画面・ウィンドウの録画を選べるChrome拡張。

仮名・開発版 v0.4.0。将来のOSS公開に向けた開発版です。GitHubは非公開リポジトリで管理し、Chrome Web Storeには未公開です。公開用名称の重複や商標は未確認です。

## Chromeへ読み込む

1. Chrome 116以上で `chrome://extensions` を開き、デベロッパーモードをONにします。
2. 「パッケージ化されていない拡張機能を読み込む」で、このリポジトリ内の **`extension/`** を指定します。
3. 通常のWebページを開き、拡張アイコンからVideoHarborを開きます。
4. 「動画を保存」で候補ごとの「保存形式」を選んで保存します。録画する場合は「画面を録画」で設定を確認して明示的に開始します。

ビルド・APIキー・アカウント登録は不要です。実行時の外部ライブラリ・サーバーは使いません。

作業画面は「動画を保存」「画面を録画」の2つです。保存候補は形式アイコンと短い情報で並び、URLは「詳細」から確認できます。録画は対象カードと音声を選んで開始し、保存方法の変更や補足は必要なときに開きます。録画中は停止操作を固定表示し、停止後は未保存と保存完了を区別します。画面の短い動きはOSの「視差効果を減らす」設定に従います。

## 実装済み

- 候補ごとに「MP4（.mp4）」または「元の形式・配信の標準」を選択。HLS/DASHと既知MP4はMP4を初期選択にし、HLSの対応TS（H.264/AAC）も再圧縮せずMP4へまとめ直して保存できる。元の形式を選べば従来のTS/WebM等を保持する。
- WebM・MOV・Oggなど未対応形式からのMP4変換は選択不可で理由を表示する。形式未取得のblobは元形式が初期選択で、MP4指定時は実データの形式を確認してから保存。拡張子だけをMP4に変えて別形式を保存しない。開始後の形式変更は不可、同じ形式の再保存では保持bufferを再利用し、形式を変えた保存では再取得する。

- video/sourceの再生元・遅延読み込み属性、直接リンク、object/embed、Open Graph・Twitter動画メタデータ、JSON-LDのVideoObject、JSON形式の動画設定、読み込み済みリソースから候補を取得。MP4/WebM等の直接URLを元ファイルとして保存。
- 既知のプレーヤー初期化・状態設定に含まれるJSONを、JavaScriptとして実行せず読み取る。動画用の設定フィールド、JSON文字列、HTML escapeされたURL、動画ファイルを直接指すiframeも取得候補に追加。
- open shadow・同一サイトの埋め込み内を探索。別サイトのiframeは、表示されたサイトへのアクセスを利用者が許可してから再探索。ページ自体を動画ファイルとして保存しません。
- 暗号化されていない終了済みHLSをローカルでまとめて保存。相対URL・マスターの画質選択・バイト範囲・fMP4初期化データに対応。最高帯域候補と標準音声を選び、MP4の映像・音声が別配信の場合も一つのMP4へまとめる。一体配信のTS/MP4も従来どおり保存（再圧縮なし）。
- 終了済みで暗号化されていない静的MP4形式DASHを保存。SegmentTemplate・SegmentTimeline・SegmentList、初期化データ、byte range、相対URL・BaseURL継承に対応し、選んだ映像・音声を一つのMP4へまとめる。
- 元ファイル型のblob動画を元ページから小分けに取得して保存。MediaSourceの分割再生用blobは判別して理由を表示。
- HLS/blobの保存中は取得量・停止操作を表示し、Chromeのダウンロード完了を確認してから完了表示。保存の中断後は再試行できます。
- 未対応の配信構成は理由を表示して中断。不明な候補は保存できる候補と区別し、録画の設定へ案内。
- 元のタブを録画（tabCapture）、またはChromeの共有pickerでタブ・画面・ウィンドウを選択（getDisplayMedia）。
- WebM録画、一時停止・再開・停止、音声の実際の有無、経過時間・容量を表示。マイクは取得しない。
- 停止後にファイルへ保存、または事前に選んだファイルへ順次書き込み。書き込み確定後だけ完了表示。
- 作業タブ間の録画排他、未保存データの置換防止、共有停止時の後処理。

## 権限とプライバシー

- `activeTab` / `scripting`: 拡張アイコンを押したページのDOMを一時的に調べます。全サイト常時アクセスは要求しません。
- optional host permissions: 別サイトの埋め込みやHLS取得に必要な場合だけ、画面に示した具体的な配信元サイトへのアクセスをChromeの確認で要求します。HTTP/HTTPS全体の宣言は実行時のサイト選択用で、全サイトの一括許可は要求しません。許可はChromeの拡張機能設定から解除できます。
- `downloads`: 利用者が選んだメディアの保存と、当拡張が開始したdownload IDの状態確認。
- `storage`: ページ候補と処理状況をChromeのsession storageに保持。作業タブを閉じると消去しますが、開始済みの一括保存は残りも継続し終了後に消去します。ブラウザ終了でも消去。
- `tabCapture`: 明示開始した元タブの映像・音声。画面共有はChrome標準pickerで対象を選びます。
- 解析・テレメトリ・アカウント・クラウド送信なし。メディア取得時はその配信元への通信が発生します。
- 候補URLは認証用query等を含む可能性があります。session内に留め、Git・ログ・不具合報告へ貼らないでください。フィードバックは合成データで再現します。
- サイトの認証情報・Cookieを独自に読み出す処理はありません。Chrome自身のdownloadと、許可した配信元へのHLS取得はブラウザの既存セッションに従います。HLS取得時はRefererを送らず、リダイレクトで別の配信元へ移動する取得は中断します。

## 制約

- 暗号化・DRM・ライブ配信、HLSのTS/AAC形式の別音声・別映像/字幕・不連続な構成、DASHのWebM・SegmentBase・複数Period・開始時刻補正が必要な構成は未対応です。子のHLS配信リスト単独では別音声の有無を判別できないため、取得中・完了時に音声が未確認と表示します。保存後に音声も確認してください。すべての動画サイトに対応するものではありません。
- HLS/DASH/blobの組み立ては映像・音声を合わせて最大256 MiB、配信の区間は合わせて5000件・配信リスト1 MiBまでです。HLSは5階層・候補全体で64配信リストまで、追加の配信元許可は1回に最大32サイトです。処理は作業タブ内で行うため、閉じる/更新/ブラウザ停止で中断します。容量は取得データの上限で、ブラウザ全体のメモリ使用量上限ではありません。
- 元の形式でHLSのTSを保存するときはTS対応プレーヤーを使用してください。MP4指定のTS変換はH.264とAACの対応構成を対象とし、他のcodec・暗号化・破損・時刻が不明な構成は理由を表示して中断します。MP4合成・TSからの変換は圧縮済みデータと時刻を保って行い、再圧縮・音声映像codecの変換・DRM回避は行いません。
- MP4合成は各配信の初期化データに1トラックが入るfragmented MP4を対象にし、映像・音声を最大1本ずつ扱います。絶対位置に依存するfragment、通常MP4のサンプル表、特殊なトラック構成は拒否します。
- 直接保存はサイトの認証・Referer制限・期限付きURLにより失敗します。ダウンロード完了と、動画としての再生確認は別です。元の形式で拡張子不明URLを保存すると `.video` です。MP4指定はMP4/M4VのURLまたはMP4系MIMEで確認できる候補だけに許可します。
- 録画は表示全体を実時間で記録し、元の動画ファイルと同じ品質・形式にはなりません。WebMが出力です。
- **録画中は作業タブを閉じないでください。** 閉じる・更新・ブラウザ停止・クラッシュで録画データが失われます。クラッシュ復旧は未実装。
- すべての録画は最大30分。メモリ保存は受信済みデータ約256 MiBで停止（最終chunkやブラウザ内部bufferで超過する場合あり）。順次保存も書込待ち量を制限します。
- 順次保存はFile System Access APIが使える環境のみ。失敗時には不完全なファイルが残る場合があります。共有pickerキャンセルは保存完了にしません。
- 音声の取得はChrome・OS・共有対象に依存。macOSの画面収録許可、実picker、タブ/システム音声、長時間・背景タブでの挙動は別途実機確認が必要です。
- 保護映像は黒画面等になる可能性があります。マイク録音、領域crop、タイマー開始は未実装です。

- Chrome設定・Web Store等、拡張を実行できないページは対象外。
- 1回の取得は最大500候補・12000要素。埋め込み画像は別途容量制限があります。制限時は通知します。
- 作業タブは各拡張で4つまで。元タブが移動した場合はそのページでアイコンを押し直してください。
- 取得済み候補を保持するため、再スキャンでDOMから消えた候補も残ります。完全に取り直すには作業タブを閉じて開き直します。
- 動的ページは、元ページで動画を再生してから再スキャンしてください。任意のJavaScriptの実行/通信監視や閉じたshadow DOMの解析は行いません。

## 開発・検証

Node.js 22以上:

```sh
npm test
npm run check
# ブラウザテストのみ開発依存が必要
npm ci
npm run test:browser
# HLS/blob/埋め込みの統合試験（ローカルffmpeg・ffprobeが必要）
npm run test:embedded
```

`npm test`内の実MP4合成試験もローカルffmpeg・ffprobeがあれば実行し、ない環境ではその試験だけSKIPします。ブラウザ統合試験は両コマンドを必須とします。

ブラウザテストはインストール済みのChromeを、個人プロファイルとは別の一時プロファイルで起動します。テストコピーだけにlocalhostのhost権限を付け、合成ページで収集・UI・保存を検証します。配布manifestにはhost権限を追加しません。録画テストは共有APIの入力を合成streamへ差し替え、実際のMediaRecorderと保存処理を検証します。実picker・activeTabアイコン操作・OS音声の検証とは分けます。`CHROME_CHANNEL`でPlaywrightのchannelを変更できます。

検証範囲と残件は [docs/QA.md](docs/QA.md)、体験と状態の設計は [docs/DESIGN.md](docs/DESIGN.md)。
