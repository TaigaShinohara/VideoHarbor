# VideoHarborの本人確認

この手順は、実際のChromeの共有picker・保存先picker・音声・結果の再生と、本人が動画を見分けられるかを確認するためのものです。自動試験の成功とは別に、実施した項目だけを記録します。

## 開始

Node.js 22以上と、このMacに既にあるffmpegを使います。追加の依存パッケージや動画ダウンロードは不要です。リポジトリで次を実行し、表示された `http://127.0.0.1:ポート/` をChromeで開きます。

```sh
npm run qa:ux
# npmの入口がまだない版ではこちら
node scripts/ux-fixture.mjs
```

`chrome://extensions`で確認対象のVideoHarborの`extension/`を読み込み、変更後なら再読み込みます。進行中の録画や未保存データがある場合は、それを先に保存してから拡張を再読み込みます。既存の作業タブでは元ページの情報を確認し、このfixtureの作業タブと取り違えないようにします。

ページには青と赤のカップがあり、約3秒の映像と異なる高さの合成音を繰り返します。音量を小さくしてから、本人が再生ボタンを押してください。青と赤のURLは同じ配信元・同じ`clip.webm`という名前で、queryだけが異なります。青には同じ映像の代替sourceもあります。下の緑の動画は`localhost`という別ホストのiframeです。すべてこのMacのループバック通信で、外部サイトへは送りません。

## 保存する動画の識別と再スキャン

目的は、ファイル名が同じでも欲しい動画を選べることと、ページの変化が現在の候補に反映されることです。

初回の理解を観察する場合は、下の操作手順を読む前に「青いカップの動画を残して、見直せる状態にしてください」という目的だけで試します。ボタンの場所や正しい候補を先に教えず、何を手がかりに選んだか、どこで迷ったかを行動の後に記録します。以下は操作・失敗回復を一つずつ確かめるための手順です。

1. fixtureで青・赤の色と音を確認し、拡張アイコンから「動画を保存」を開きます。
2. 青と赤が別の動画として並び、青の代替sourceが同じ動画の候補として扱われることを確認します。必要なら「元ページで確認」を押し、対応する動画の位置が示されることと、短い強調が消えることを見ます。
3. 青を保存します。「保存場所を表示」から保存したファイルを開いて再生し、青いカップと青の音であることを確認します。実ファイル名も照合します。赤でも同様に確認し、同名ファイルの区別を実際の映像で確かめます。直接保存の候補に、画面内再生の操作があるとは扱いません。
4. 元ページで「赤を新しい動画へ差し替える」を押し、拡張で再スキャンします。新しい緑の動画が現在の候補へ入り、削除した赤のDOM候補が現在の動画として残らないことを確認します。赤の読み込み済みURLが読み込み履歴に出る場合は、現在の動画との区別が付くことを見ます。前回の結果や保存済みの結果も確認します。
5. 再スキャン後も保存済みの結果を確認できることを確かめます。「赤の動画へ戻す」で繰り返せます。

終了条件は、欲しかった色の動画を保存・再生でき、差し替えた動画と履歴を本人が区別できることです。判断に迷った表示はその文言と場面を残します。候補が見つかっただけで再生確認済みにはしません。

## 別ホストiframeの拒否と再試行

目的は、どの埋め込みに追加サイト許可が必要なのかを分かることです。

1. 最初の追加サイト確認で`localhost`への許可をいったんキャンセルまたは拒否します。元ページや青・赤の保存が使えることを確かめます。
2. 再試行の操作から、Chromeの確認に表示された`localhost`だけを許可し、再スキャンします。広い全サイトの許可は選びません。
3. 埋め込みの緑のカップを保存して再生し、映像と音を確認します。許可済みで確認が出ない場合は「拒否」は未実施と記録します。拒否確認のために、普段使っているサイトの許可をまとめて変更しないでください。

終了条件は、拒否後に再試行でき、必要な埋め込みを取り違えずに確認できることです。metadataだけの埋め込みヒントについて、画面上の位置が判明したとは扱いません。

## 元タブ録画・実音声・停止後の結果

目的は、実際のタブ映像と音声を録画し、結果を確認できることです。

1. fixtureの青だけを再生し、「画面を録画」で「元のタブ」と音声を選びます。マイクは使いません。開始したらfixtureへ戻り、5〜10秒ほど青いカップと音を確認します。
2. 停止後に作業タブへ戻ります。未保存の表示と、停止した録画のプレビューが同時に分かることを確認します。
3. プレビューを再生し、青い映像・実際に聞こえる合成音・長さを確認します。音声ありという表示だけで音が聞こえたとはしません。
4. ファイルへ保存し、完了表示と実ファイルの再生を照合します。結果を見たまま次の録画設定へ進めることも確認します。

終了条件は、映像と音が実ファイルで再生でき、未保存と完了を取り違えないことです。無音・黒画面・長さの違いがあれば、その項目は失敗または未確認として残します。

## Chromeの共有pickerと取消

目的は、Chrome標準の共有選択を本人が操作し、キャンセルしても前の結果を失わないことです。

1. 前の結果を表示した状態で、別のタブ・画面・ウィンドウを選ぶ録画を開始し、Chromeの共有pickerを一度キャンセルします。前の結果を再生できることを確認します。
2. もう一度開始し、共有pickerでこのfixtureのタブを明示的に選びます。音声の選択肢がある場合はその表示と選択内容を記録します。短く録画して停止し、結果の映像と音を再生します。
3. 画面・ウィンドウも確認する場合は、私的な内容を映さない状態を自分で準備してから、対象を一つずつ選びます。共有中表示を確認し、Chrome側の「共有を停止」でも結果へ戻ることを見ます。OSの画面収録許可が必要なら本人が操作します。

終了条件は、選んだ対象の映像が結果へ入り、取消時に前の結果を維持できることです。タブで音が入った結果を、画面やウィンドウのシステム音声まで確認済みとは扱いません。各対象の音を個別に記録します。

## 事前に保存先を選ぶ方式を2本続けて使う

目的は、File System Access APIの実picker、保存先の再選択、書き込み確定と取消後の回復を確認することです。普段のファイルを上書きしないよう、この確認専用の新しいファイル名を使います。

1. 「保存方法」を開いて「ファイルへ順次保存」へ変え、保存先pickerを開いて一度キャンセルします。前の結果が残り、保存先未選択の状態が分かることを確認します。
2. pickerで`videoharbor-check-1.webm`などの新しいファイルを選び、青を5秒ほど録画して停止します。書き込み確定中と保存完了を区別し、完了後に実ファイルを再生します。
3. 2本目へ進みます。次の保存先を選ぶ前に、その状態が分かることを確認します。pickerを一度キャンセルし、1本目の結果を確認できることを見ます。
4. `videoharbor-check-2.webm`という別の新しい保存先を選びます。赤を録画して停止し、完了後に2本の実ファイルをそれぞれ開き、1本目が青、2本目が赤で上書きされていないことを確認します。
5. 未保存データからの保存でChromeが保存先確認を表示する設定の場合は、そのダイアログも一度キャンセルし、未保存データが残って再試行できることを確認します。ダイアログを出さないChrome設定の場合は、この取消だけ未実施とします。

終了条件は、2本が別ファイルとして再生でき、各取消で前結果や未保存データを失わず、保存完了の表示が実ファイルと一致することです。API非対応や権限拒否で実施できない場合は、その状態を記録します。

## 記録と終了

各項目について、Chrome・OS・確認対象の版、実施日、成功／失敗／未実施、見た映像、実際に聞こえた音、迷った操作、残ったファイル名を記録します。URL queryに認証情報を含む実サイトで同じ記録をする際は、そのURLを貼り付けないでください。

録画を停止して必要な結果を保存し、fixtureのタブを閉じ、ターミナルでCtrl+Cを押します。サーバーは終了し、このプロセスが一時ディレクトリへ生成した動画だけを削除します。本人が保存した確認ファイル、拡張のサイト許可、ブラウザ設定は変更しません。

このfixtureは、合成動画の保存・録画・再生と本人の操作確認に使います。全サイトへの対応、認証や期限付きURL、DRM、実際の音の品質、30分録画、最大容量、すべての利用者の理解を保証する確認ではありません。未実施の本人確認を自動試験の成功で埋めないでください。
