# 安定性修正・検証記録 — 2026-11-04 / v0.6.4

## 対象と結果

レビュー4件を対象に、PR #32（停止・録画制御）、#33（未保存データ・共有結果）、#34（downloads APIなしの直接保存）を統合した。追加の最終点検で、wake lock・許可判断の応答待ちも中断可能にした。解析送信・実行時外部依存・manifest権限の追加はない。

## 状態と保持

- ファイル保存完了は、Chrome downloadsのcompleteまたは順次writer.close成功で確定する。OS共有先への受け渡しは別の結果として表示する。
- Web Shareの非対応・拒否・キャンセル・その他の例外で成功表示へ進まない。受け渡し後も、共有先でのファイル確定は拡張から確認できない。
- 保存準備用の保持枠は作業タブにつき1件。未保存または共有後のBlobを、別候補・形式変更・再スキャン・失敗で削除しない。次の取得は保存確定または明示破棄後に行う。
- 取得済みFileの再共有は、最初のawaitより前にクリックからshareを呼ぶ。許可要求・wake lock・元URLの再取得を挟まない。
- 準備済み動画のパネルは、再スキャンで元候補が消えた後も保存・共有と破棄の操作を保持する。
- 保持はメモリ上のみ。タブ更新・終了・ブラウザ停止・プロセス破損からのデータ復旧は保証しない。保持枠256 MiBと録画の既存容量制限は、ブラウザ全体のRSS上限ではない。

## 停止と資源の所有

録画ロックの変更と制御は、download/scan用の直列キューから分離した。blob取得は長いexecuteScriptを共通キュー外で待ち、workspaceが閉じられた後の結果は採用しない。共有状態の変更は既存の直列化を維持し、録画ロックの二重取得・別instanceの解放を防ぐ。

blob準備は60秒、chunkは10秒、解放の待機は2秒に制限する。元frameでも取得開始前に所有tokenとAbortControllerを登録し、readerを中断する。期限切れ、取消し済み、別の処理に置換済みの結果はsnapshotへ公開しない。解放が準備より先に到着した場合もtokenの取消し記録で開始を拒否する。記録は件数を制限し、メディアやURLは含めない。

workspaceの停止は、元frameの応答・解放を待たずに処理中状態を抜ける。実際に凍結中のframeへ即時の資源解放を強制するAPIはないため、解放要求と期限・再開後の検査を併用する。タイムアウトだけでChrome側の処理を取消したとは扱わない。Chromeが受付済みのdownloadは実際の終端を照合し、結果不明の自動再送は行わない。

wake lockの取得は2秒のbest effortとし、停止後に遅れて取得されたlockも解放する。許可判断の待機も取消し可能にし、遅い許可が停止済み処理を再開しない。UI更新の例外で取得・解放を止めない。

## downloads APIがない環境の直接保存

Chromeの直接downloadは既存方式を維持する。downloads APIなしの場合は、具体的hostの許可を確認して作業タブから取得し、共有用の実ファイルを準備する。URLだけの共有に置き換えない。

HTTP 200の全体応答、許容MIME、実データの形式、Content-Lengthとの整合、空データ、最大256 MiBを確認する。圧縮されたHTTP応答ではencoded Content-Lengthをdecoded bytesと比較しない。Content-Lengthがない応答もstreamingで容量を制限する。取得と各reader.readは30秒まで待ち、停止・失敗時はreaderを解放する。リダイレクトは拒否し、credentials/referrerの既存方針を維持する。

MP4/MOVはWorkerで上位boxの完全性・必要box・構造数上限を確認する。WebM/OggはMIMEと先頭識別を照合する。これらは任意のcodecや全サンプルの正常性を保証する検査ではない。未知・非対応形式をmp4へ改名して保存しない。

## 耐久試験

初回の実時間試験は11分後にタブvisibilityがvisibleとなり、「非選択・非表示を維持する」という試験条件を満たさなくなったため中断扱い。録画障害と断定しない。再試験は専用headless Chromeで同じ実時計・30分の製品上限・非選択タブ条件を維持する。時計を短縮する合成試験で代用しない。

再試験PASS（Chrome 156.0.8078.80）。実録画時間1,800,494 ms、実経過1,804,205 ms、一時停止2,248 ms。非選択タブ・hidden条件を維持し、製品の30分上限で自動停止した。29,582,508 bytes（約28.2 MiB）のWebMに映像と音声を確認し、映像終端1,800.367秒、全編decodeに成功した。入力track終了・合成音声生成器のclose・録画lock解放・結果破棄後のidle復帰を確認。時計と上限の改変、実OS picker/実システム音声の使用はない。耐久対象のrecorder.jsは最終runtimeと一致することをハッシュで確認した。

## Safariの検証境界

iOS 18.5 / iPhone 16シミュレータ用の独立QAアプリを変換・ビルド・導入した。変換器の生成した親appとextensionのbundle ID不整合は一時QAプロジェクト内だけで修正した。既存アプリは置き換えず、表示名で識別した専用拡張にlocalhostだけを1日許可した。

合成MP4/HLSの検出、直接MP4の取得と実Worker検査、操作権限が切れた後のデータ保持、明示的な再共有によるiOS標準共有シート（137 KB、動画、写真/ファイルへの保存項目）の表示を確認した。共有前の検証版はPR #34のruntimeで、最終のwake lock/許可取消し追補は単体とChromeで検証する。

共有シート内の保存先ボタンは、この実行環境の操作ツールから押下できなかったため、当初は本人操作待ちとした。その後、2026-11-04に、写真への保存・ファイルへの保存と、両方の映像・音・約4秒の再生確認を案内し、本人から「できた」との報告を受領した。この案内に対する本人確認として記録し、今回のシミュレータ保存確認の待機を解除した。AIによる保存済みファイルの独立検査や物理iPhoneでの確認とは区別する。物理iPhoneの署名・導入・保存、OS sleepを伴う実録画は今回の確認済み範囲に含めない。

## 再開と更新

今回のレビュー4件への対応とシミュレータ保存確認は完了。追加の物理端末検証やOS sleep確認は、具体的な依頼時に別途再開する。物理端末へ導入する場合は、既存アプリやデータを置換しないQA識別子と既存の署名手段を確認し、本人の追加認証や新規の署名/provisioningが必要ならその操作を本人へ戻す。
