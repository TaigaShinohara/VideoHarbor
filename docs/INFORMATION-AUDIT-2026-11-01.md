# 機密情報・個人情報の点検 — 2026-11-01

## 結果

基準は `main` の `6efd9f5` / v0.6.0。拡張に同梱する `extension/` 全27ファイルでは、実際のAPIキー、秘密鍵、固定パスワード、外部サービス用トークン、開発者の個人情報、私的なメディア、解析用の送信先の埋め込みは見つからなかった。

リポジトリ全体を「個人情報も内部情報も一切ない」とは扱わない。開発文書には内部Notionのページ識別子とGitHubの所有者が分かる参照があり、Gitの作者・コミッター情報には作者名・メールアドレスがある。また、利用者が扱うURL・題名・映像・音声・保存先は個人情報を含み得る。以下に所在と保持範囲を分けて記録する。値そのものは転載しない。

## 調査範囲と方法

| 対象 | 確認範囲 |
| --- | --- |
| 現行ソース | 開始時点の追跡70ファイル。実行用27ファイル、文書、テスト、スクリプト、manifest、lockfile、ライセンス、ignore設定 |

| Git | ローカル・取得済みremoteの全ref、reflog、到達不能objectを含む470 object中の全285 blob、全51 commit objectのメッセージ。ref/reflogから到達するcommitは47件。集計は今回の監査記録をcommitする前 |

| 依存 | Playwrightの開発用コード・文書・ライセンス。製品の実行時依存はなし |

値を出さないローカル検査で、秘密鍵ヘッダー、主要providerの資格情報形式、JWT、資格情報の固定文字列、URL内の認証値・署名query、メール、個人ホームpath、内部文書リンク、アカウント参照、電話番号形式、プライベートIP、高エントロピー文字列を探索した。Git作者の識別文字列と現行ファイルも照合した。ファイル名と行・種別だけを出し、候補をコードとテストの文脈で確認した。

既製のGitleaks/TruffleHogはこの環境にインストールされておらず、今回使用していない。独自のパターン検査・候補の文脈確認・コード経路のレビューであり、未知形式の秘密を数学的に否定する検査ではない。ローカル検査用スクリプトと値を含まない中間集計は一時領域だけで使用し、製品へ追加していない。

GitHubの古いref・reflog・到達不能objectも検査対象にしたため、現行ファイルの編集だけで履歴の情報が消えるとは判断していない。GitHubサーバー側の削除済みref、外部バックアップ、他clone、個人Chromeプロファイル、既存の実ダウンロードフォルダは今回の対象外。

## 利用時に扱う情報

| 情報 | 使用・保存先 | 保持と通信 |
| --- | --- | --- |
| 元ページ・メディアURL、ページ/動画題名、frame/document識別子 | 作業タブのメモリ、Service Workerの `chrome.storage.session` | ブラウザ終了で消去。作業タブ閉鎖時は原則sessionを除去するが、進行中の直接保存は終了まで継続 |
| 動画のプレビュー画像 | ページ内で作った最大160×90のJPEG。画像1件32 KiB、snapshot全体256 KiBまで | メモリ/session。外部のサムネイルサービスへ送信しない |
| HLS/DASH/blob・録画本体 | 元frame、作業タブ、同梱Workerのメモリ、利用者が選んだファイル | 外部解析サービスなし。WorkerへのprotocolにURLや保存先を含めない |
| 保存先の絶対path | Chrome downloadの状態確認結果からsessionまたは作業タブメモリへ取得 | 通常の結果一覧はbasenameで表示。外部送信なし |
| ファイル名・保存済みメディア・Chrome download履歴 | 利用者のファイルシステム、Chrome | 作業タブやsessionの消去後も残る。元のメディア情報・顔・音声・画面内の文字を自動匿名化しない |

外部通信は利用者が保存する配信元への取得とChromeのdownload。HLS/DASH取得は具体的サイトの許可とブラウザ既存セッションのcredentialsを使用し、Refererなし・redirect拒否。直接downloadはChromeのCookie/redirect方針に従う。Cookieの独自読出し、解析SDK、consoleへの候補/認証値出力、`localStorage` / IndexedDB / `chrome.storage.local` / `sync`への保存は実装されていない。

メッセージは同じ拡張のworkspaceかつ該当sessionの作業タブから受け付ける。動画だけの録画では操作UUID・lock所有者・frame/document/実video要素も照合する。UUIDはローカル操作の識別子で、外部サービスの認証トークンではない。

## 保持・画面表示の注意点

1. `extension/workspace-videos.js:52` の「詳細」はqueryを含む候補URLの先頭500文字を表示する。署名や認証queryが含まれる場合、画面共有やスクリーンショットへ写り得る。URLを不具合報告やGitへ添付しない。機能を変えるURL削除や無条件のquery除去は今回行っていない。
2. ページ/動画題名を保存フォルダ・録画ファイル名に使う。題名に個人情報があればファイル名にも残る。Chrome履歴・保存済みファイルはsessionとは別であり、拡張の終了で自動消去されない。
3. 直接保存の進行中に作業タブを閉じた場合、`items/previousItems/history`は消すが、`videoElements/frames/title/url`等は残りの保存が終了するまでsessionに残る（`extension/background.js` の閉鎖処理）。外部送信や恒久storageにはつながらないが、今後の保持最小化の候補として記録。今回の調査では挙動を変更していない。

## 先行したPR対応

開始時点の全19 PRはマージ済みでopenは0件だった。reviews、comments、review threadsを確認し、PR #5に残っていた未解決指摘2件を現行コードでも再現した。

- MP4選択時の実download応答で `application/ogg` を見逃す問題を、既存のMIME/保存形式判定で修正。MP4/M4V、元形式選択、不明/汎用MIMEの既存扱いは維持。
- AVC sliceの先頭検査を64byteで切り出した結果、正常なescapeのlookaheadが欠ける問題を修正。全NALのviewから上限63byteだけ処理し、圧縮bytesと処理予算を保持。不正・実際の途中切れescapeは引き続き拒否。

両方とも修正前の回帰失敗を確認し、修正後の対象37テストはPASS、SKIPなし。全体の検証結果は `QA.md` に記録する。

## 検証の限界

この点検は機密/個人情報の混入とデータの流れを対象にした。実アカウントでの秘密取得、実サイトへの送信、個人プロファイルの読み取り、既存の私的録画の再生は行っていない。実OS picker・実音声・利用者の体験・任意サイトでの互換性・公開適否の最終承認とは別である。
